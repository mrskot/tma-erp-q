# ЗАИНТЕРЕСОВАННЫЕ СТОРОНЫ TMA-ERP

## Ключевые заинтересованные стороны

### 1. Владелец продукта / Бизнес-заказчик
**Роль:** Определяет требования, приоритеты, утверждает изменения
**Интересы:**
- Соответствие системы бизнес-процессам
- Сокращение времени обработки заявок
- Улучшение качества продукции
- Снижение операционных затрат

**Влияние:** Высокое (утверждение требований, приемка)
**Участие:** Активное на всех этапах

### 2. Конечные пользователи
#### 2.1 Мастера (Masters)
**Роль:** Создают заявки на контроль продукции
**Интересы:**
- Простота и скорость создания заявок
- Мобильный доступ через Telegram
- Прозрачность статусов заявок
- Минимальное время на обучение

**Влияние:** Среднее (обратная связь, тестирование)
**Участие:** Регулярное (ежедневное использование)

#### 2.2 Инспекторы ОТК (OTK Inspectors)
**Роль:** Проводят контроль, фиксируют результаты
**Интересы:**
- Удобный интерфейс для фиксации результатов
- Доступ к чек-листам продуктов
- Возможность работы с мобильных устройств
- История проведенных контролей

**Влияние:** Среднее (обратная связь, тестирование)
**Участие:** Регулярное (ежедневное использование)

#### 2.3 Администраторы системы
**Роль:** Управляют системой, настраивают процессы
**Интересы:**
- Простота администрирования
- Надежность системы
- Возможность настройки без программирования
- Мониторинг и отчетность

**Влияние:** Среднее (настройка, поддержка)
**Участие:** Периодическое (настройка, мониторинг)

### 3. Команда разработки
#### 3.1 Разработчики
**Роль:** Проектирование, разработка, поддержка
**Интересы:**
- Четкие требования и спецификации
- Современный технологический стек
- Качественная документация
- Возможность для профессионального роста

**Влияние:** Высокое (реализация, архитектура)
**Участие:** Постоянное

#### 3.2 Тестировщики (если есть)
**Роль:** Обеспечение качества
**Интересы:**
- Тестовая документация
- Возможность автоматизации тестирования
- Раннее вовлечение в процесс

**Влияние:** Среднее (контроль качества)
**Участие:** На этапах тестирования

### 4. Технические заинтересованные стороны
#### 4.1 DevOps / Системные администраторы
**Роль:** Развертывание, мониторинг, поддержка инфраструктуры
**Интересы:**
- Стабильность и надежность
- Простота развертывания
- Мониторинг и алертинг
- Масштабируемость

**Влияние:** Среднее (инфраструктура)
**Участие:** На этапах развертывания и поддержки

#### 4.2 Архитекторы
**Роль:** Проектирование архитектуры
**Интересы:**
- Соответствие стандартам
- Масштабируемость решения
- Интеграция с другими системами

**Влияние:** Высокое (архитектурные решения)
**Участие:** На этапах проектирования

### 5. Внешние заинтересованные стороны
#### 5.1 Руководство предприятия
**Роль:** Стратегическое руководство
**Интересы:**
- ROI (возврат инвестиций)
- Улучшение бизнес-показателей
- Конкурентные преимущества
- Соответствие регуляторным требованиям

**Влияние:** Высокое (бюджет, стратегия)
**Участие:** На ключевых этапах

#### 5.2 Клиенты предприятия
**Роль:** Конечные потребители продукции
**Интересы:**
- Качество продукции
- Своевременность поставок
- Прозрачность процессов

**Влияние:** Косвенное (через качество продукции)
**Участие:** Опосредованное

## Коммуникационные каналы

### Регулярные коммуникации:
1. **Ежедневные стендапы** - для команды разработки
2. **Еженедельные встречи** - с владельцем продукта
3. **Демонстрации** - показ прогресса пользователям
4. **Обратная связь** - через Telegram, email, встречи

### Документация:
1. **Система промтов** - текущая документация
2. **Техническая документация** - API, база данных
3. **Пользовательская документация** - руководства, инструкции
4. **Отчеты** - прогресс, метрики, проблемы

## Ожидания и требования

### Ожидания владельца продукта:
1. Система соответствует бизнес-процессам
2. Сокращение времени обработки на 50%
3. Улучшение прозрачности процессов
4. Возврат инвестиций в течение года

### Ожидания пользователей:
1. Простота и интуитивность интерфейса
2. Надежность и стабильность
3. Быстрая поддержка и решение проблем
4. Постоянное улучшение системы

### Ожидания разработчиков:
1. Четкие и неизменные требования
2. Современный технологический стек
3. Возможность для профессионального роста
4. Баланс между качеством и сроками

## Управление изменениями

### Процесс внесения изменений:
1. **Инициатива** - любая заинтересованная сторона
2. **Анализ** - оценка влияния, стоимости, сроков
3. **Приоритизация** - совместно с владельцем продукта
4. **Реализация** - разработка и тестирование
5. **Внедрение** - развертывание и обучение

### Критерии принятия изменений:
1. Соответствие бизнес-целям
2. Техническая реализуемость
3. Соотношение стоимость/польза
4. Влияние на существующий функционал
