## Правила использования промтов

### 1. Контекст
Перед использованием любого промта:
- Прочитай INDEX-CONTEXT.md
- Проверь UPDATES-PENDING.md
- Изучи связанные документы

### 2. Кастомизация
Каждый промт должен быть адаптирован под конкретную задачу:
- Замени [заполнители] реальными значениями
- Уточни требования если необходимо
- Добавь контекст проекта

### 3. Документирование
После выполнения задачи:
- Обнови CHANGELOG-DETAILED.md
- Обнови UPDATES-PENDING.md
- Проверь актуальность документации

### 4. Качество
Все промты должны соответствовать:
- Стандартам кода из developer-guide.md
- Архитектурным принципам из concepts.md
- Требованиям безопасности из consolidated.md

## Примеры использования

### Пример 1: Создание нового endpoint
```
Создай новый API endpoint для TMA-ERP-Q:

Endpoint: GET /api/reports/quality-metrics
Описание: Возвращает метрики качества по участкам

Параметры:
- date_from: Дата начала периода
- date_to: Дата окончания периода
- lot_id: Фильтр по участку (опционально)

Требования:
1. Аутентификация через JWT
2. Авторизация для ролей inspector, director, admin
3. Пагинация результатов
4. Валидация параметров
5. Кэширование на 5 минут
6. Экспорт в CSV

Ожидаемый результат:
- Модель, сервис, контроллер
- Маршрут и middleware
- Тесты и документация
```
