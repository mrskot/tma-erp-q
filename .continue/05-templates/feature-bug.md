## Процесс работы с шаблонами

### Для новых функций:
1. Создать задачу по шаблону Feature Request
2. Обсудить с командой и стейкхолдерами
3. Утвердить требования и дизайн
4. Реализовать функцию
5. Протестировать и проверить критерии приемки
6. Документировать изменения
7. Развернуть в production
8. Провести ретроспективу

### Для исправления ошибок:
1. Создать задачу по шаблону Bug Fix
2. Воспроизвести и подтвердить ошибку
3. Определить приоритет и серьезность
4. Найти root cause и предложить решение
5. Реализовать и протестировать исправление
6. Валидировать исправление
7. Документировать изменения
8. Развернуть исправление
9. Принять профилактические меры

## Интеграция с системой промтов

### Связь с промтами:
- Каждая функция/ошибка должна иметь связанные промты
- Промты используются для реализации и документации
- Изменения в промтах отражаются в шаблонах

### Обновление INDEX-CONTEXT.md:
При создании новой функции или исправлении серьезной ошибки:
1. Обновить статус в INDEX-CONTEXT.md
2. Добавить запись в CHANGELOG-DETAILED.md
3. Обновить UPDATES-PENDING.md если необходимо

### Версионирование:
- Функции: увеличивают minor версию (1.2.0 → 1.3.0)
- Исправления ошибок: увеличивают patch версию (1.2.0 → 1.2.1)
- Критические исправления: могут требовать hotfix релиза

## Примеры

### Пример Feature Request:
```markdown
**ID:** FR-202601-001
**Название:** Автоматическое назначение контролёров
**Приоритет:** High
**Статус:** Approved

**Описание:**
В текущей системе контролёры назначаются вручную администратором.
Нужно реализовать автоматическое назначение на основе загрузки контролёров.

**Пользовательские истории:**
Как администратор,
Я хочу чтобы заявки автоматически назначались доступным контролёрам,
Чтобы уменьшить ручную работу и ускорить обработку заявок.

**Критерии приемки:**
Given Есть заявка в статусе "новая"
And Есть доступные контролёры
When Система обрабатывает заявку
Then Заявка назначается контролёру с наименьшей загрузкой
And Статус меняется на "назначена"
And Контролёр получает уведомление в Telegram
```

### Пример Bug Fix:
```markdown
**ID:** BF-202601-001
**Название:** Ошибка валидации telegram_id при регистрации
**Приоритет:** Critical
**Серьезность:** Blocker

**Описание:**
При регистрации пользователя с telegram_id содержащим буквы возникает ошибка 500.

**Шаги для воспроизведения:**
1. Отправить POST /api/auth/register
2. В теле запроса указать telegram_id: "abc123"
3. Получить ошибку 500 вместо валидационной ошибки

**Root cause:**
Валидатор ожидает числовое значение, но telegram_id передается как строка.

**Решение:**
Изменить валидацию чтобы принимать строки, содержащие только цифры.
```
